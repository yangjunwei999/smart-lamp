# 屿光民宿智能氛围床头灯 · SMART_LAMP

STM32F103C8T6 + RGB 三路 PWM + 无源蜂鸣器 + 双按键的智能床头灯固件。
甲方订单的 6 条需求全部落地，工程可直接编译、烧录、现场演示。

> 适用：STM32F103C8T6 最小系统板 / 开发板套装 + ST-Link，CubeIDE 打开即用。

---

## 项目概述

本项目是「屿光民宿智能床头灯」订单的固件交付物，主控为 STM32F103C8T6，通过 TIM3 的三个通道输出 10 kHz PWM，分别驱动 RGB 灯珠的红、绿、蓝三路；TIM4 输出可变频 PWM 驱动无源蜂鸣器；两个按键（KEY1 / KEY2）承担全部人机交互。

设计目标不是"能亮"，而是把甲方的模糊词（"仪式感"、"不刺眼"、"一次成功"）翻译成**可测量、可现场复现的时序与参数**：0.4 s 静默、2.5 s 二次缓动渐亮、1 s 双脉冲收尾、20 ms 消抖、1.2 s 长按判定、30 s 唤醒曲线、2 Hz 火警快闪。所有参数都以宏定义写在 `main.c` 的「用户配置区」，改一个数就能改行为。

系统为裸机实现：主循环 + SysTick 时基，10 ms 一个光效计算节拍，不使用 RTOS（理由见「软件架构」）。

## 功能特点

对照甲方订单 6 条需求，逐条给出实现方式与现场验收手段：

| 编号 | 甲方需求 | 实现方式 | 现场验收方式 |
|------|----------|----------|--------------|
| ① | 仪式感点亮：开灯瞬间要有记忆点 | 上电 0.4 s 静默 → 2.5 s 二次缓动渐亮至 30% 暖金 → 1 s 双脉冲收尾（30→60→30→55→30），全程约 3.9 s | 上电复位，看完整 4 s |
| ② | ≥3 种灯光模式，客人可自切 | 4 种：常亮暖光 / 柔和呼吸 / 流光幻彩 / 深夜微光，KEY1 短按循环 | 连按 KEY1，数模式 |
| ③ | 深夜模式不刺眼，盯看 10 s 不晃眼 | 固定深琥珀 CCR 9/5/1（约 9% 占空比） | 切到深夜模式，盯灯 10 s |
| ④ | 早 7 点温柔唤醒，代替闹钟 | KEY1 长按 1.2 s 模拟 7 点，30 s 内亮度 2%→60%、色温 深琥珀→暖白，尾段 3 声轻鸣（间隔渐缓） | 长按 KEY1，等 30 s |
| ⑤ | 火警紧急警示：刺眼警示 + 声音报警 | KEY2 一键触发：红灯全亮 + 2 kHz 蜂鸣，2 Hz 快闪；任意状态可打断，再按解除 | 在任意模式下按 KEY2 |
| ⑥ | 按键一次成功，不能连按两次才响应 | 20 ms 电平稳定确认 + 事件边沿化，短按在松手时产生、长按在 1.2 s 达标时产生且只产生一次 | 快速连按 10 次，每次只切一档 |

**已知的口径差异**：需求 ④ 原文是"早 7 点"，本工程用 KEY1 长按**模拟**唤醒时刻，未接 RTC、未做联网校时（见「已知限制」）。答辩时应主动说明这是"演示用触发方式"，不要声称已实现真实定时。

### 灯珠极性与上电自检

代码内置 7 s 上电自检（见「关键机制 6」），用来在**没有任何仪器**的情况下判断灯珠是共阴还是共阳：

- 自检第 2 段（占空比全开 99）灯亮、第 3 段（全灭 0）灯灭 → 共阴，保持 `LED_INVERT = 0`；
- 反之灯在"全灭"段亮 → 共阳，把 `LED_INVERT` 改为 1 重新编译。

## 软件架构

### 总体结构

- 裸机单主循环，无 RTOS：本系统只有"读按键 → 算光效 → 写寄存器"三类工作，10 ms 节拍足以覆盖全部实时性要求，引入 RTOS 只会增加栈与优先级调度的复杂度。
- 时基统一用 `HAL_GetTick()`（SysTick，1 ms），所有时序判断都是"当前 tick − 起点 tick ≥ 阈值"，**不使用 `HAL_Delay` 做主流程**（这正是早期版本火警按不动的根因）。
- 光效更新被 `(now - lastTick) >= 10` 限流为 10 ms 一次；按键扫描每轮主循环都执行，靠 20 ms 稳定窗口消抖。
- PWM 只改 CCR，不改 ARR（除蜂鸣器变频），因此调光是"改一个数"，无重配置开销。

### 顶层状态机

| 状态 | 进入条件 | 行为 | 退出 |
|------|----------|------|------|
| `ST_RITUAL` | 上电 | 静默 → 渐亮 → 双脉冲 | 时序结束或 KEY1 短按 → `ST_RUN` |
| `ST_RUN` | 仪式结束 / 火警解除 / 唤醒结束 | 4 种灯光模式循环 | KEY1 长按 → `ST_WAKE`；KEY2 → `ST_FIRE` |
| `ST_WAKE` | KEY1 长按 1.2 s | 30 s 亮度+色温双曲线，尾段 3 声轻鸣 | 30 s 结束 → `ST_RUN`；短按跳过 / 长按取消 → `ST_RUN` |
| `ST_FIRE` | KEY2 按下 | 红灯 2 Hz 快闪 + 2 kHz 蜂鸣 | KEY2 再按解除 → `ST_RUN` |

**优先级**：`ST_FIRE` > `ST_WAKE` > `ST_RITUAL` / `ST_RUN`。火警判断写在主循环最前面，且 `ST_FIRE` 期间 KEY1 全部被屏蔽，保证警示不会被模式切换打断。

### 灯光模式

| 模式 | 亮度 / 颜色 | 周期或特性 |
|------|-------------|------------|
| `MODE_WARM` 常亮暖光 | 暖色 30%（R:G:B = 100:55:8） | 静态 |
| `MODE_BREATH` 柔和呼吸 | 暖色 0-99% | 10 ms 步进 ±1，单程约 1 s，整周期约 2 s |
| `MODE_FLOW` 流光幻彩 | HSV 色环，明度 80% | 45°/s，转满一圈 8 s |
| `MODE_NIGHT` 深夜微光 | CCR 9/5/1（约 9%） | 静态，深琥珀 |

### 按键事件模型

| 事件 | 产生时机 | 消费方 |
|------|----------|--------|
| `KEVT_DOWN` | 电平稳定 20 ms 且确认为按下 | KEY2（火警触发/解除，按下即响应） |
| `KEVT_SHORT` | 松手时，且本次按压未触发长按 | KEY1（切模式 / 跳过仪式 / 跳过唤醒） |
| `KEVT_LONG` | 按住满 1.2 s 时立即产生，一次按压只产生一次 | KEY1（进入或取消唤醒） |

## 关键机制

### 1. 仪式感点亮：二次缓动 + 双脉冲

渐亮段把时间归一化到 0-255，再套二次缓动 `e = u * (510 - u) >> 8`（等价于抛物线，慢起—快升—柔收），最后映射到 30% 目标亮度。全套只用整数移位，无浮点、无查表，10 ms 一算对 M3 无压力。

选二次而不是线性，是因为线性渐亮在低亮度段人眼会感觉"突然就亮了"；二次曲线在 0-15% 段走得慢，起光更接近日出。

收尾双脉冲用四段折线（30→60 用 250 ms、60→30 用 250 ms、30→55 用 200 ms、55→30 用 300 ms），像一次深呼吸，把"记忆点"做在最后 1 s。

### 2. 按键：20 ms 稳定确认 + 事件边沿化

状态机保存四个量：原始电平、消抖后电平、原始电平最近变化时刻、本次按下起始时刻。规则只有三条：

1. 原始电平一变，只记时刻，不产生事件；
2. 电平**稳定保持 20 ms** 才翻转"消抖后电平"，按下时产生 `DOWN`，松手时产生 `SHORT`（若长按已触发则不再产生短按）；
3. 按住满 1.2 s 立即产生一次 `LONG` 并置标志，松手不再重复。

因此"一次物理按压"在事件层永远是"一个动作"，从根上消除双跳。

### 3. PWM 调光：10 kHz 载波，CCR 即亮度

- TIM3：计数时钟 1 MHz（PSC = 71），ARR = 99，载波 = 1 MHz / 100 = **10 kHz**，CCR 填 0-99 直接等于亮度百分数。
- 10 kHz 远高于人眼闪烁融合频率，视觉上绝对不闪；同时开关损耗对普通三极管仍可接受。
- 颜色用比例合成：暖光 R:G:B = 100:55:8；深夜微光是同一套比例压到 9%。亮度与色温因此可以**解耦**成两条独立曲线（这是需求 ③ 与 ④ 冲突的解法）。

### 4. 火警：主循环首部的抢占式处理

KEY2 的事件判断写在主循环第一段，先于所有光效计算；一旦进入 `ST_FIRE`，10 ms 节拍只跑火警分支（前 250 ms 红灯全亮 + 蜂鸣，后 250 ms 全灭静音 → 2 Hz），其它状态全部不参与运算。解除时统一关蜂鸣、回 `ST_RUN`。

### 5. 温柔唤醒：30 s 亮度 / 色温双曲线

- 亮度：`p = t*255/30000`，`e = p*p/255`（缓入，前段几乎无感），再映射到 2%→60%；
- 色温：绿分量 30→55、蓝分量 0→8、红分量固定为满量程，随 `p` 线性插值，实现"深琥珀 → 暖白"；
- 声音：尾段共 **3 声**轻鸣，分别在 20.0 s / 24.0 s / 28.5 s 触发，每声 60 ms、3 kHz、10% 占空比；间隔 4.0 s → 4.5 s **逐渐放缓**，不是机械的固定节拍——越到后面越"舍不得叫"，避免像闹钟。

### 6. 上电自检：7 s 证明"灯和喇叭是活的"

顺序：6 次 250 ms 亮 / 250 ms 灭（RGB 全亮 + 2 kHz 蜂鸣，共 3 s）→ 占空比全开 99 持续 2 s → 全灭 0 持续 2 s。
目的有二：任何接线/极性错误都能在自检阶段暴露；同时给评委一个"板子确实在跑"的第一印象。

### 7. 时钟兜底

优先 HSE 8 MHz × 9 = 72 MHz；若晶振起振失败，自动回退 HSI/2 × 9 继续运行，不会卡死在 `Error_Handler`。PWM 的 PSC 由 `HAL_RCC_GetPCLK1Freq()` 现算，因此换时钟源后 PWM 频率仍准确。

## 已知限制与后续计划

1. **无 RTC / 无联网校时**：需求 ④ 的"7 点"目前用 KEY1 长按模拟。若要做真定时，需外接 DS3231 或增加 ESP8266 NTP 校时。
2. **无环境感知**：未接光敏电阻与人体感应，不做自动调光与有人/无人判断。
3. **单机版**：未做云端上报与手机控制（订单未要求）。
4. **未制 PCB**：开发板 + 杜邦线形态，长期使用建议转 PCB 以提高接触可靠性。
5. **无串口日志**：未做 printf 重定向，排障依赖上电自检的灯/声反馈与调试器观察寄存器。
6. **报警为软件模拟**：火警由 KEY2 触发，未接烟感探头。

后续若扩展，优先级建议：RTC 定时 > 光敏自动调光 > 烟感输入 > 联网上报。
